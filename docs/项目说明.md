# PINECONE CLUB · 松果游戏社

## 1. 项目定位

一个双人联机小游戏合集：20 款规则各不相同的小游戏，两个人在两台设备上开一间房就能玩。名字、视觉、代码全部独立重写，和本机以前做过的任何项目没有关系。

- 目录：`D:\codexAI\pinecone-club`
- 端口：4460
- 仓库：`yjj0339/pinecone-club`
- 线上：https://yjj0339.github.io/pinecone-club/

## 2. 功能清单

### 大厅
- 昵称输入，存在本机浏览器。
- 20 款游戏卡片：手写 SVG 封面、组别、预计时长、一句话规则。
- 点任意卡片直接开房；也可「随机开一间房」。
- 六位房号加入；邀请链接自动带房号。
- 本机战绩（只存本机浏览器）。
- 连接状态、实时延迟、音效开关、玩法与服务器设置入口。

### 房间
- 大号房号 + 复制房号 / 复制邀请链接。
- 两张座位票：昵称、房主/你、在线/掉线/已准备。
- 系列赛长度 1 / 3 / 5 局（房主可调）。
- 准备 / 取消准备；两人都准备后 3 秒倒计时，服务端统一切换开局。
- 房主可换游戏；离开房间会关闭房间并通知对方。

### 对局
- 服务端权威：操作上行 → 引擎校验 → 状态下行；客户端只渲染。
- 顶部记分板：双方系列赛胜场、当前局数、总剩余时间 / 回合剩余时间。
- 对局舞台由每款游戏自己的视图渲染（DOM 或 Canvas）。
- 表情四连（有冷却），认输、离开。
- 掉线冻结计时并显示横幅；60 秒内恢复继续，超时判负。

### 结算
- 本局胜负与原因、系列赛比分、本局比分（若引擎提供）。
- 再来一局（双方都点 → 下一局）、换游戏（房主）、回大厅。
- 系列赛打满后自动开启新一轮并清零系列比分。

### 断线与恢复
- 每个玩家有 token 身份牌，存在本机 localStorage。
- 刷新页面 / 网络抖动后自动 `resume`；同一座位旧连接会被新连接替换并提示。
- 只有一人在线时对局冻结，不会偷走回合。

## 3. 技术结构

```
client/main.js      应用状态机：大厅 / 房间 / 对局 / 结算
client/net.js       Socket.IO 封装、服务器发现、延迟、序号
client/game.js      视图注册表：20 个 mount 适配
client/art.js       品牌、主视觉、20 张手写 SVG 封面
client/audio.js     WebAudio 音效（无音频文件）
client/styles.css   纸品视觉系统
server/index.js     HTTP + Socket.IO + 静态托管 + SQLite 战绩
server/rooms.js     房间状态机、倒计时、时钟、暂停、结算
shared/catalog.js   20 款游戏元数据
shared/protocol.js  事件名、阶段、限制
games/<id>.engine.js 纯函数引擎（服务端运行）
games/<id>.view.js   视图（浏览器运行）
games/registry.js    服务端引擎注册表
```

### 引擎契约

```js
create(seed, now) -> state
act(state, player, action, now) -> boolean
step(state, now) -> boolean
view(state, player) -> object
```

- 引擎不读时钟、不读随机源；全部由服务端传入，保证同种子可复现。
- `view` 按玩家裁剪隐藏信息；所有下划线字段不外泄。
- 回合制游戏用 `kit.begin/turnOver`；同时行动的游戏 `state.simultaneous = true` 且 `turn = -1`。

### 对局时钟与暂停

- 服务端维护 `gameStartAt / pausedTotal`，对局时间 = `now - gameStartAt - pausedTotal`。
- 掉线即暂停：`step` 与计时全部冻结；恢复后补算暂停时长。
- 服务端 tick 约 25Hz，推进 `step` 并下行快照；操作被接受时立即补推一帧。

### 协议事件

| 方向 | 事件 | 作用 |
| --- | --- | --- |
| C→S | `create` / `join` / `resume` | 开房 / 加入 / 恢复座位 |
| C→S | `select` / `ready` | 选游戏与系列赛 / 准备 |
| C→S | `act` | 携带单调递增 seq 的游戏操作 |
| C→S | `again` / `change` / `leave` / `resign` | 下一局 / 换游戏 / 离开 / 认输 |
| C→S | `emoji` / `ping` | 表情 / 延迟 |
| S→C | `snap` | 个性化快照（含该玩家可见的 game view） |
| S→C | `emoji` / `closed` / `notice` / `hello` | 表情、关闭、通知、握手 |

所有请求带 ack：`{ ok, code?, message? }`；重复 seq 返回 `DUPLICATE`，非法操作返回 `MOVE`，限流返回 `SLOW`。

### 数据

- 对局结束写入 `runtime/data/pinecone.sqlite` 的 `matches` 表（id、game、players、winner、ended、record JSON）。
- 本机战绩只存在浏览器 localStorage，不上传。

## 5. 运行

- 双击 `启动松果游戏社.cmd`：构建 → 起服务 → 起 Cloudflare 临时隧道 → 同步地址到线上 → 打印本机/公网地址。
- 双击 `停止松果游戏社.cmd`：只关闭本项目记录的进程与 4460 端口上属于本项目的进程，不碰其他项目。
- 双击 `发布到 GitHub.cmd`：构建 → 推 main → 推 gh-pages → 开启 Pages。

## 6. 边界与风险

- 公网联机依赖本机服务端和 Cloudflare 临时隧道：电脑关机、服务停止、隧道重开换地址后，旧地址失效。启动脚本会把新地址同步到线上页面。
- GitHub Pages 只有前端，不能代替服务端。
- 真实异地设备联机受网络环境影响，验收时只在本机双客户端 + 公网地址访问两种条件下验证，不声称验证过异地真实设备。
- 房间只支持两个人；第三人加入会被拒绝。
