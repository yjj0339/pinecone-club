# 制作提示词

这份文档记录 PINECONE CLUB 是怎么被要求和构建出来的，方便以后复刻或继续迭代。

## 1. 用户目标

> 做一个双人联机小游戏合集，至少 20 款小游戏，两个人在两台设备上开房间一起玩。要浅色、精致、不要模板感。有昵称入口、六位房号、邀请链接、大厅选游戏、准备、同步开局、对局、结算、再来一局/换游戏、3/5 局系列赛；服务端权威，断线能重连，错误要如实提示。要能一键启动/停止，部署到 GitHub Pages，后端放在 D 盘用 Cloudflare Tunnel 暴露。

补充约束：

- 全部放在 `D:\`，不占 C 盘，不动本机已有项目。
- 代码零注释；中文界面；不要深色主题。
- 先完成、再自测、再部署，不能交付占位符。
- 名字必须和以前做过的任何项目不同（不能叫 DUO PLAY、双人游乐场之类的名字）。

## 3. 构建方式

### 第一阶段：骨架与契约

- 定技术栈：Vite（前端，原生 ES 模块）、Node 24 + Socket.IO（权威服务端）、SQLite（战绩）。
- 写 `docs/CONTRACT.md`：引擎接口、视图接口、kit 工具、视觉令牌、测试要求、协作红线。
- 写 `shared/catalog.js`（20 款游戏元数据）、`games/kit.js`、五子棋参考实现（引擎 + 视图）。

### 第二阶段：并行实现游戏

按组拆给多个执行者，每人只写自己组的 `games/<id>.engine.js`、`games/<id>.view.js` 和一份测试：

| 组 | 游戏 |
| --- | --- |
| board | 五子棋（参考实现）、雾中舰队、点格领地、黑白棋、雷区漫步 |
| puzzle | 记忆翻牌、灵光问答、2048 对决、数独竞速、回声序列 |
| action | 桌面冰球、铁皮坦克、泡泡爆破、长蛇竞技、落块对战 |
| duel | 弹弓攻城、迷宫夺旗、石头剪刀布、抢拍反应、打字竞速 |

硬性要求：状态可 JSON 序列化、随机只用 seed、非法输入返回 false、`view` 裁剪隐藏信息、视图自注入样式、移动端可用、零注释。

### 第三阶段：房间与前端

- `server/rooms.js`：创建/加入/恢复、准备、倒计时、对局时钟、暂停、结算、系列赛、再来一局、换游戏、表情、限流。
- `server/index.js`：HTTP 健康检查、静态托管、Socket.IO 事件接线、SQLite 写入。
- `client/main.js`：大厅 / 房间 / 对局 / 结算四种界面状态机，断线恢复，邀请链接，战绩，弹窗，音效。
- `client/art.js`：品牌标识、主视觉、20 张 SVG 封面。

### 第四阶段：验证与部署

- `npm test`：引擎测试 + 服务端流程测试。
- `npm run qa`：真双客户端联机冒烟（创建、加入、准备、开局、操作、同步、掉线、恢复、认输、再来一局、换游戏、离开、房号失效）。
- 浏览器检查：本机双窗口完整走一局；公网地址再走一遍；320px 与桌面两种视口截图。
- `scripts/publish.ps1` 发布 Pages；`scripts/start.ps1` 起服务与隧道；`scripts/stop.ps1` 只停本项目。

## 4. 验收口径

- 测试输出必须是真实运行结果，不写"应该通过"。
- 公网可达性用实际 HTTP 请求与浏览器控制台验证。
- 异地真实设备受条件限制，未验证就明确写"未验证"。
- 已知风险、失败场景、未覆盖项都要写进 `docs/验收记录.md`。
